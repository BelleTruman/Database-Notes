# 关系型数据库设计

电商系统的核心业务数据通常存储在关系型数据库中，包括用户、商品、订单、支付等模块。关系型数据库能够提供ACID事务保证，确保数据的强一致性，这对于订单和支付等关键业务至关重要。

## 数据库选型

### MySQL
- **优势**：成熟稳定、生态丰富、性能优秀
- **适用场景**：中小型电商平台，对成本敏感的场景
- **推荐引擎**：InnoDB（支持事务和外键）

### PostgreSQL
- **优势**：功能强大、扩展性好、支持复杂查询
- **适用场景**：大型电商平台，需要复杂数据分析的场景
- **特色功能**：JSON支持、全文搜索、地理位置查询

## 核心表设计

### 1. 用户模块

#### 用户表（users）
```sql
CREATE TABLE users (
    user_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(20) UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    salt VARCHAR(64) NOT NULL,
    nickname VARCHAR(100),
    avatar_url VARCHAR(255),
    gender TINYINT COMMENT '0-未知, 1-男, 2-女',
    birthday DATE,
    status TINYINT DEFAULT 1 COMMENT '0-禁用, 1-正常',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_phone (phone),
    INDEX idx_email (email),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 用户地址表（user_addresses）
```sql
CREATE TABLE user_addresses (
    address_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    receiver_name VARCHAR(50) NOT NULL,
    receiver_phone VARCHAR(20) NOT NULL,
    province VARCHAR(50) NOT NULL,
    city VARCHAR(50) NOT NULL,
    district VARCHAR(50) NOT NULL,
    detail_address VARCHAR(255) NOT NULL,
    postal_code VARCHAR(20),
    is_default TINYINT DEFAULT 0 COMMENT '0-否, 1-是',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE,
    INDEX idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户地址表';
```

### 2. 商品模块

#### 商品分类表（categories）
```sql
CREATE TABLE categories (
    category_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    parent_id BIGINT DEFAULT 0 COMMENT '父分类ID，0表示顶级分类',
    category_name VARCHAR(100) NOT NULL,
    level TINYINT NOT NULL COMMENT '分类层级，1-一级, 2-二级, 3-三级',
    sort_order INT DEFAULT 0,
    icon_url VARCHAR(255),
    status TINYINT DEFAULT 1 COMMENT '0-禁用, 1-启用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_parent_id (parent_id),
    INDEX idx_level (level)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品分类表';
```

#### 商品表（products）
```sql
CREATE TABLE products (
    product_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    category_id BIGINT NOT NULL,
    product_name VARCHAR(200) NOT NULL,
    product_no VARCHAR(50) UNIQUE NOT NULL COMMENT '商品编号',
    brand VARCHAR(100),
    main_image VARCHAR(255),
    price DECIMAL(10,2) NOT NULL COMMENT '售价',
    original_price DECIMAL(10,2) COMMENT '原价',
    stock INT DEFAULT 0 COMMENT '库存数量',
    sales INT DEFAULT 0 COMMENT '销量',
    description TEXT COMMENT '商品描述',
    detail TEXT COMMENT '商品详情',
    status TINYINT DEFAULT 1 COMMENT '0-下架, 1-上架',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (category_id) REFERENCES categories(category_id),
    INDEX idx_category_id (category_id),
    INDEX idx_product_no (product_no),
    INDEX idx_price (price),
    INDEX idx_sales (sales),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';
```

#### 商品SKU表（product_skus）
```sql
CREATE TABLE product_skus (
    sku_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    product_id BIGINT NOT NULL,
    sku_no VARCHAR(50) UNIQUE NOT NULL COMMENT 'SKU编号',
    sku_name VARCHAR(200) NOT NULL,
    attributes JSON COMMENT 'SKU属性，如{"颜色":"红色","尺码":"L"}',
    price DECIMAL(10,2) NOT NULL,
    stock INT DEFAULT 0,
    image VARCHAR(255),
    status TINYINT DEFAULT 1 COMMENT '0-禁用, 1-启用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (product_id) REFERENCES products(product_id) ON DELETE CASCADE,
    INDEX idx_product_id (product_id),
    INDEX idx_sku_no (sku_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品SKU表';
```

### 3. 订单模块

#### 订单表（orders）
```sql
CREATE TABLE orders (
    order_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_no VARCHAR(50) UNIQUE NOT NULL COMMENT '订单号',
    user_id BIGINT NOT NULL,

    payment_amount DECIMAL(10,2) NOT NULL COMMENT '实付金额',
    freight_amount DECIMAL(10,2) DEFAULT 0 COMMENT '运费',
    discount_amount DECIMAL(10,2) DEFAULT 0 COMMENT '优惠金额',
    payment_method TINYINT COMMENT '1-支付宝, 2-微信, 3-银行卡',
    payment_time TIMESTAMP NULL COMMENT '支付时间',
    delivery_time TIMESTAMP NULL COMMENT '发货时间',
    receive_time TIMESTAMP NULL COMMENT '收货时间',
    order_status TINYINT NOT NULL DEFAULT 1 COMMENT '1-待付款, 2-待发货, 3-待收货, 4-已完成, 5-已取消',
    receiver_name VARCHAR(50) NOT NULL,
    receiver_phone VARCHAR(20) NOT NULL,
    receiver_province VARCHAR(50) NOT NULL,
    receiver_city VARCHAR(50) NOT NULL,
    receiver_district VARCHAR(50) NOT NULL,
    receiver_address VARCHAR(255) NOT NULL,
    remark VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    INDEX idx_user_id (user_id),
    INDEX idx_order_no (order_no),
    INDEX idx_order_status (order_status),
    INDEX idx_created_at (created_at)
```

#### 订单明细表（order_items）

```sql
CREATE TABLE order_items (
```

### 5. 库存模块

#### 库存表（inventory）
```sql
CREATE TABLE inventory (
    inventory_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sku_id BIGINT NOT NULL,
    warehouse_id BIGINT NOT NULL COMMENT '仓库ID',
    available_stock INT NOT NULL DEFAULT 0 COMMENT '可用库存',

    INDEX idx_sku_id (sku_id)
```


## 分库分表策略

### 垂直拆分
将不同业务模块的表拆分到不同的数据库：
- **用户库**：users, user_addresses
- **商品库**：categories, products, product_skus
- **订单库**：orders, order_items
- **支付库**：payment_records
- **库存库**：inventory, inventory_logs

### 水平拆分
对于数据量特别大的表进行水平拆分：

#### 订单表分片
- **分片键**：user_id
- **分片规则**：user_id % 16
- **优势**：同一用户的订单在同一分片，查询用户订单无需跨库

#### 订单明细表分片
- **分片键**：order_id
- **分片规则**：与订单表保持一致
- **优势**：订单和订单明细在同一分片，避免分布式事务

## 索引优化

### 索引设计原则
1. **高频查询字段**：为经常出现在 WHERE 条件的字段建立索引
2. **组合索引**：遵循最左前缀原则
3. **避免过度索引**：索引会影响写入性能
4. **覆盖索引**：查询字段都在索引中，避免回表

### 常用组合索引
```sql
-- 订单表组合索引
ALTER TABLE orders ADD INDEX idx_user_status_time (user_id, order_status, created_at);

-- 商品表组合索引
ALTER TABLE products ADD INDEX idx_category_status_sales (category_id, status, sales DESC);

-- 订单明细表组合索引
ALTER TABLE order_items ADD INDEX idx_order_product (order_id, product_id);
```

## 事务处理

### 下单流程事务
```sql
START TRANSACTION;

-- 1. 创建订单
INSERT INTO orders (...) VALUES (...);

-- 2. 创建订单明细
INSERT INTO order_items (...) VALUES (...);

-- 3. 扣减库存（乐观锁）
UPDATE inventory 
SET available_stock = available_stock - ?, 
    locked_stock = locked_stock + ?,
    version = version + 1
WHERE sku_id = ? 
  AND warehouse_id = ? 
  AND available_stock >= ?
  AND version = ?;

-- 4. 记录库存流水
INSERT INTO inventory_logs (...) VALUES (...);

COMMIT;
```

### 支付成功流程
```sql
START TRANSACTION;

-- 1. 更新订单状态
UPDATE orders 
SET order_status = 2, 
    payment_time = NOW()
WHERE order_no = ? 
  AND order_status = 1;

-- 2. 更新支付记录
UPDATE payment_records
SET payment_status = 3,
    callback_time = NOW(),
    callback_data = ?
WHERE payment_no = ?;

-- 3. 释放锁定库存，扣减可用库存
UPDATE inventory
SET locked_stock = locked_stock - ?,
    total_stock = total_stock - ?
WHERE sku_id = ? AND warehouse_id = ?;

COMMIT;
```

## 性能优化建议

1. **读写分离**：主库写入，从库读取
2. **慢查询优化**：定期分析慢查询日志，优化SQL
3. **连接池配置**：合理配置数据库连接池大小
4. **批量操作**：使用批量插入和更新减少数据库交互
5. **缓存策略**：热点数据缓存到Redis
6. **异步处理**：非核心流程异步化，如发送通知、记录日志等

## 数据一致性保证

1. **乐观锁**：库存扣减使用version字段
2. **分布式锁**：秒杀场景使用Redis分布式锁
3. **幂等性设计**：支付回调接口保证幂等性
4. **事务补偿**：分布式事务失败时的补偿机制
5. **最终一致性**：通过消息队列保证数据最终一致

## 备份与恢复

1. **定期全量备份**：每天凌晨进行全量备份
2. **实时增量备份**：通过binlog进行增量备份
3. **异地容灾**：主要数据库异地备份
4. **恢复演练**：定期进行数据恢复演练
